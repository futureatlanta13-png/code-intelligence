# Code Intelligence

Готовый автономный статический сайт **SEO Workflow Automation** для `https://codeintelligence.ru`.
Публичные тексты — на английском. HTML5, CSS3 и небольшой vanilla JavaScript; никаких npm, сборки, серверной части, внешних шрифтов, трекеров или CDN.

## Структура

```text
code-intelligence/
├── index.html
├── privacy/index.html
├── terms/index.html
├── assets/
│   ├── css/styles.css
│   ├── js/main.js
│   └── img/
│       ├── social-preview.svg
│       └── social-preview.png
├── tools/update-contact.ps1
├── favicon.svg
├── robots.txt
├── sitemap.xml
├── 404.html
├── CNAME
├── .nojekyll
└── README.md
```

`privacy/index.html` и `terms/index.html` обеспечивают адреса `/privacy/` и `/terms/`. `.nojekyll` отключает обработку Jekyll. Корневые пути подходят для собственного домена и локального HTTP-сервера. До подключения домена проектный адрес вида `USERNAME.github.io/REPOSITORY/` не поддерживает эти корневые пути: используйте локальный сервер или сразу собственный домен. Для сайта `USERNAME.github.io` корень также подходит.

## Как открыть локально

Для проверки всех ссылок и маршрутов используйте HTTP-сервер из корня проекта. Установка зависимостей не нужна, если Python уже установлен:

```powershell
cd code-intelligence
python -m http.server 8080
```

Откройте адрес локального сервера на порту 8080, затем `/privacy/`, `/terms/` и `/404.html`. Для остановки нажмите Ctrl+C. Любой другой статический сервер с корнем в этой папке тоже подходит. Двойной щелчок по HTML не обеспечивает правильную работу корневых путей.

Python нужен только для локального предпросмотра; на GitHub Pages он не используется. Простая локальная раздача не имитирует автоматическую страницу 404: её проверьте напрямую по `/404.html`. GitHub Pages сам показывает файл `404.html` для отсутствующих страниц.

## Контактный email

Единая JavaScript-константа `CONTACT_EMAIL` находится в `assets/js/main.js`. Начальное значение — `contact@codeintelligence.ru`. HTML содержит рабочие статические ссылки для пользователей с отключённым JavaScript.

Чтобы заменить адрес одновременно в константе и во всех статических HTML-ссылках, выполните из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\update-contact.ps1 -Email "your-real-email@example.com"
```

Скрипт — необязательная локальная утилита редактирования, не сборщик и не часть сайта. Он не делает сетевых запросов. При ручном редактировании константы замените старый адрес также во всех четырёх HTML-файлах.

**До публикации и Google OAuth verification убедитесь, что контактный ящик действительно существует, принимает письма и регулярно проверяется.** GitHub Pages не создаёт почтовые ящики: настройте почту отдельно у вашего провайдера.

## Как опубликовать через GitHub Pages

1. Создайте отдельный репозиторий GitHub. Загрузите **содержимое этой папки в корень** репозитория; `index.html`, `CNAME` и `.nojekyll` должны находиться в корне, а не внутри дополнительной папки `code-intelligence`.
2. В репозитории откройте **Settings → Pages**.
3. В **Build and deployment** выберите **Deploy from a branch**, затем вашу ветку (обычно `main`) и **/(root)**. Сохраните.
4. В **Custom domain** укажите `codeintelligence.ru`, без `https://` и без пути. Сохраните. Файл `CNAME` уже содержит это значение.
5. Настройте DNS согласно разделу ниже и дождитесь успешной проверки в Pages.
6. Включите **Enforce HTTPS**, когда сертификат станет доступен.
7. Проверьте три публичных URL и страницу 404 по произвольному несуществующему пути.

Выбран способ публикации из ветки без workflow, сборки и Actions-конфигурации. Подробнее: [документация GitHub о публикации из ветки](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Домен и DNS

Проверьте владение доменом в GitHub Pages: в настройках вашего аккаунта или организации, в разделе Pages добавьте домен и создайте предложенную **TXT-запись**. Её имя и значение индивидуальны; скопируйте их из GitHub. [Инструкция GitHub по подтверждению домена](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages).

Для корневого домена создайте четыре **A-записи** с именем `@` (или пустым именем, если так обозначается корень у вашего DNS-провайдера):

| Тип | Имя | Значение |
| --- | --- | --- |
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME, если нужен www | www | YOUR-USERNAME.github.io |

Эти IPv4-значения сверены с официальной документацией GitHub 6 октября 2026 года. **Перед настройкой повторно сверьте их с [актуальной документацией GitHub Pages](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)**. Для аккаунта организации используйте `YOUR-ORGANIZATION.github.io`; путь репозитория в DNS не добавляется.

Вместо A-записей допустим поддерживаемый вашим провайдером **ALIAS / ANAME** для `@` на `YOUR-USERNAME.github.io`. Выберите один способ. Если добавляете IPv6, возьмите актуальные **AAAA-записи** из документации GitHub и используйте вместе с A-записями. Не оставляйте для сайта конфликтующие старые A/AAAA-записи; почтовые MX/TXT-записи сохраняйте. Не создавайте wildcard `*` для Pages. При настроенном apex-домене и `www` GitHub поддерживает перенаправление на выбранный основной домен.

DNS может обновляться до 24 часов. Имя GitHub-аккаунта и записи проверки владения нужно подставить вручную.

## HTTPS

После успешной проверки DNS дождитесь выпуска сертификата и включите **Settings → Pages → Enforce HTTPS**. Проверьте, что `http://codeintelligence.ru` перенаправляется на `https://codeintelligence.ru`. Все локальные ресурсы используют безопасные корневые пути; смешанного контента в проекте нет.

Если переключатель недоступен, проверьте DNS и статус сертификата по [инструкции GitHub по HTTPS](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https). Не добавляйте лишние DNS-записи в попытке ускорить выпуск сертификата.

## Google OAuth verification

Укажите в настройках приложения:

| Поле | Значение |
| --- | --- |
| Application name | Code Intelligence |
| Homepage | https://codeintelligence.ru/ |
| Privacy Policy | https://codeintelligence.ru/privacy/ |
| Terms of Service | https://codeintelligence.ru/terms/ |
| Authorized domain | codeintelligence.ru |

Это публичный сайт продукта, а не реализация Google OAuth. Authorized JavaScript origins и redirect URIs задайте по **реальному приложению**; не добавляйте выдуманный OAuth callback на GitHub Pages. Секреты OAuth и токены никогда не помещайте в этот репозиторий.

До подачи на проверку:

- [ ] Домен открывается через HTTPS без ошибки сертификата.
- [ ] Homepage доступна без авторизации.
- [ ] Privacy Policy доступна по `/privacy/`.
- [ ] Terms доступны по `/terms/`.
- [ ] Ссылки в header и footer работают на каждой странице.
- [ ] Контактный email существует и принимает письма.
- [ ] Домен подтверждён владельцем способом, требуемым Google; при необходимости — через Search Console. Подтверждение в GitHub не заменяет проверку Google.
- [ ] Google OAuth application использует то же название и домен, что сайт.
- [ ] OAuth scopes соответствуют только реально реализованным функциям приложения.
- [ ] Фактические доступ, хранение, передача и удаление данных соответствуют Privacy Policy.
- [ ] Google account подключается добровольно, а объяснение типов данных и назначения доступа показано внутри приложения перед авторизацией.
- [ ] Пользователь может отозвать доступ и направить запрос на удаление; существует рабочий процесс обработки таких запросов.
- [ ] При новых целях использования или новых разрешениях приложение получает необходимое согласие.

Сверьте фактический состав обрабатываемых данных, используемых провайдеров и сроков хранения. Тексты не заявляют конкретную инфраструктуру, сертификацию, юридическое лицо или юрисдикцию. Если реальные процессы отличаются, исправьте раскрытия до публикации. Готовность публичных страниц не подтверждает соответствие реализации приложения и сама по себе не гарантирует Google verification. Дополнительные требования зависят от scopes.

Источники для сверки: [Google API Services User Data Policy](https://developers.google.com/terms/api-services-user-data-policy) и [Google Workspace user data and developer policy](https://developers.google.com/workspace/workspace-api-user-data-developer-policy).

## Редактирование и технические детали

- Дизайн: `assets/css/styles.css`; адаптивные стили для desktop, laptop, tablet и mobile.
- Тексты и метатеги: соответствующий `index.html`. После изменения страниц обновляйте дату политики при необходимости.
- SVG-графика главной встроена в HTML; favicon и изображение для социальных сетей локальные. `social-preview.svg` — редактируемый исходник, `social-preview.png` — готовая картинка 1200×630 для Open Graph. При изменении исходника обновите PNG.
- Канонические URL и Open Graph привязаны к `https://codeintelligence.ru`; если домен меняется, обновите HTML, `CNAME`, `robots.txt` и `sitemap.xml`.
- JavaScript изменяет только контактные ссылки; без него весь контент, навигация, оглавления и CTA работают.
- Анимация схемы и переходы отключаются при `prefers-reduced-motion`. Для юридических страниц предусмотрены стили печати.
- Сайт не устанавливает cookies и не хранит данные в localStorage/sessionStorage. Внешние ссылки выполняют переход только по действию пользователя; автоматических внешних запросов нет. Хостинг может обрабатывать технические журналы доставки сайта.

Файлы готовы к загрузке в GitHub Pages. Репозиторий, DNS, почтовый ящик и настройки Google OAuth нужно настроить в ваших аккаунтах.
